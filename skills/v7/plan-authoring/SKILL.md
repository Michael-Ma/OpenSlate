# OpenSlate plan authoring

Ordinary creative planning saves writing, not executable generation source. Read [the current guidance](references/grammar.md) and [the creative-patch example](references/example.md). Follow the production skill's Reply style. Obtain current head/revision, saved IDs, media and settled choices from paged context; do not invent identities.

For clear typed proposal decisions in a fresh user editing turn, use `accept_proposal` / `reject_proposal` with `{proposalId}` as described in [the grammar](references/grammar.md). Identify the proposal by letter, subject or a clear reference to the only held proposal; if several are open and the message is ambiguous, ask which one. After success, report the decision and that accepted changes can be undone, then continue other requested work using the accepted prompts. Video still requires the clicked `confirm_video` card after frames are opened.

Never author image, review or video declarations (`p.image`, `p.humanReview`, `p.approvedImage`, `p.video`), and never use `requestNewTakes`. The application builds all keyframe and video work; `make_keyframes` requests keyframes and needed voice lines, while video requires human scene confirmation. Never combine creative edits with `source` in one `prepare_change`. Only separate timeline and render source remains available when actually needed; Film exports are assembled by the application without Director source.

For harmless writing, use `prepare_change` with `variant: "project"`, current `expectedHeadVersion` and `creative`, then apply its returned prepared ID. Create shots before reading their service-issued IDs. Use short scene `title` and descriptive `purpose`; put coverage, timing and narration range in `story`. Framing is a 1–3-word label of at most 40 characters (Close-up, Medium, Wide).

On shots with current or retained media, changes to purpose, action, framing, motion, prompts, duration or narration use `propose_change` and a note linking its proposalId. Retained voice or accepted cues also establish media impact. Pure text without media impact may apply directly with a receipt. Respect `PROPOSAL_REQUIRED` and human field conflicts, never split an edit to bypass them. The full 6.0.0 proposal fields are described in the grammar. Global canonical narration editing and invented acceptance/timing fields are unavailable.

In Plan save direction. When the person asks for keyframes in a fresh editing conversation, call `make_keyframes` within that scope. In Keyframes the person may also press "Make keyframes". For requested video in ready scenes, record a scene-anchored `confirm_video` note choice for each, with `reply` when useful. Say: "Confirm in this chat or in Keyframes." They review exact frames, motion, narration and video recipe before the click. Scene confirmation saves exact script, recording and measured timing together. Listening and recording edits are optional. Film contains clips, soundtrack and export; Assets contains saved media. Name these views/actions directly.

Use `make_keyframes` only for scenes/shots explicitly requested in the fresh human editing message, using the application's returned work and price as evidence. `regenerate: true` requires explicit `shotIds` and a request for new takes. If the shots are unclear or you propose a remake, offer a `regenerate_keyframe` note choice; existing takes stay in history. Link media-impact proposals with a `proposal` choice for acceptance in chat. For video, "yes", "ok" or "go ahead" replies do not confirm: point to the open choice, or offer a fresh one if stale or settled. Report a start only after the application reports it. Reviews, review replies, automatic, discuss-only and read-only turns cannot start paid work. For recognition of an audio attachment sent with that fresh editing request, existing transcription may start when its words are requested or needed; other audio tools save pending suggestions for a human press; never declare new speech/transcription source or pass suggestions to `apply_change`. Configured keys need no approval or usage allowance.

Keep unchanged work and operation identities. After an uncertain response inspect receipts using the original identity and stop dependent changes if unresolved; never resubmit blindly. Refresh/reprepare actual conflicts, stop after revoked authority and preserve request-owned holds. The executor owns scheduling, technical retries and unknown submission reconciliation. Tool success proves saved data, not artistic quality.
