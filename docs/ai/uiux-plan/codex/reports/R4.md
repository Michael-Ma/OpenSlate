# R4 — scene runners and narration recovery

## Done

- **narration-speech-plan-stale:** standalone speech now verifies preserved visual operations against their immutable source project when current shot metadata no longer recompiles the saved graph. The current request, project, section, voice and profile fences remain. Preparation creates no visual grant or project mutation. Backup inspection uses the same isolated verification. Own/sibling motion, duration and video-prompt edits work through Confirm and voice-only Make keyframes, including existing video plans. Missing original history has its own `NARRATION_PLAN_REBASE_REQUIRED` error with an explicit regenerate-keyframes recovery message.
- **narration-orphaned-paid-voice:** attach/accept freshness is scoped to the stepped shot's narration, segment and profile. A succeeded exact take is reused at attach and omitted from every pending-work quote. A dedicated host completion path can store the original paid recording after Director chat supersedes its request, while refusing changed words/voice/profile/section, a different shot/run, or replacement of newer audio. It grants neither timing acceptance nor more generation authority. A later human press accepts the saved take without another speech call. Local attachment and unpublished acceptance checkpoints refresh only unrelated global tokens after exact receipt lookup; an unpublished stale acceptance gets a new persisted free-operation key. Committed command bodies remain unchanged for replay.
- **narration-keyframes-run-invisible:** overview publishes the latest `keyframesRun` and blocks with `confirmation_running` while any scene run is active. An out-of-range accept is deferred per shot: later shots are still voiced and stored on the first press; the run then ends blocked, naming the first shot that needs fit.
- **video-03:** confirmation and full runner freshness use `confirmationFramesCurrent`. Confirm refuses frames absent from their image binding's own outputs. An unadmitted attach rechecks full scene/frame fences instead of waiting forever. Image generation is refused while the scene's video confirmation runs, including a confirmation that arrives during composition.
- **video-05:** runner video publication uses transaction-current head/revision/holds and the original scene intent, guard and exact frame pins. Stable receipt identities exclude ephemeral film-head tokens; legacy saved tokens are used only to recover a committed historical receipt. Up to three free pre-publication compositions preserve other scenes' newly published plans/aliases. Hold narrowing includes scenes added during composition. Ordinary public generation keeps its existing compare-and-swap checks.
- **plan-impact-clip-unpriced / narration-voice-price-missing:** `oneClip` and `oneVoice` are independent one-unit locked-profile quotes, including normal unknown-price/subscription rules; absent profiles omit the unit quote.
- **narration-fit-contract-drift:** measured non-fitting lines expose server-computed whole-second `fitSeconds` from `narrationFitFrames`, bounded by the locked video profile. Estimated lines and impossible extensions omit it.
- **Supporting core repair:** a preserved node may advance only its shot revision metadata when its entire effective operation remains identical. This lets a sibling clip compose after narration acceptance; changed specifications, arguments, inputs and review gates remain refused.

## Open issues

- **Authority decision:** storing an exact completed paid take is application-owned completion under the original checked human shot scope. It does not continue a superseded request, transfer holds, accept timing or grant generation. Chat can therefore leave the run explicitly blocked at accept; the next human press uses the stored audio at zero new speech cost.
- **Bounded recomposition:** three total free video compositions are allowed when unrelated plans move. Continued churn ends with a stale-review blocker for another human press; it never retries a provider operation.
- **Fit decision:** when the actual extend operation cannot fit within the locked model/studio bounds, `fitSeconds` is absent rather than advertising an extension the server would refuse.
- **Lock boundary:** the pure one-unit quote helper omits missing video/speech profiles. The existing scene reader still requires an image and video profile to open a generation scene; this card does not widen that existing setup boundary.
- **Rare history damage:** missing immutable visual history now returns the specific `NARRATION_PLAN_REBASE_REQUIRED` error and regenerate-keyframes message before any spend. The lead owns adding a browser message/action mapping for this code; the shared run view carries only its code, and this card forbids web edits. Ordinary motion/duration/prompt edits no longer use this recovery branch.
- **Verification boundary:** rendered browser acceptance remains with the lead under the no-browser rule. No live-provider quality or production acceptance is claimed.
