# G1 — Director generation blocks

## Done

- **G1.1 Record:** each refused scene creates one immutable `director_generation_block`, scoped to the original project, request, epoch and invocation/scene key. Its insertion and the refusal receipt checkpoint share a transaction. Existing started-scene publication remains independent.
- **G1.2 View:** every turn exposes `effects.blocked`, including `[]` when empty. The projection reconstructs the exact `DirectorGenerationBlock` fields and attempt summaries; it carries no release path/body, provider payload, prompt, recovery instructions or native prose. Limits apply across all calls in a turn: the first 20 recorded scene blocks and at most 20 attempt summaries in total, using `GENERATION_BLOCKER_LIMIT`.
- **G1.3 Lifecycle:** records remain original-turn history after subsequent edits, release, fresh generation and late completion. Recording a refusal does not reassert paid authority: it must still work when the refusal itself reports that the original epoch was fenced or the film stopped.
- **G1.4 Store/recovery:** blocks have the same project/request/epoch reference validation and immutability protection as generation effects. Generic database backup/restore already retains entity kinds; no DDL or migration is needed. Exact invocation-scoped block evidence can reconcile an incomplete refused-only receipt without dispatching it again. An empty interrupted call cannot borrow another call's blocks.
- **G1.5 Tests/review:** added and extended the regressions below. Self-review of source and test diffs, plus an independent source/test review, found no outstanding must-fix issue. Review also checked callers expecting the complete effects object; their empty-state expectations now include `blocked: []`.

### Refusal codes and `shotIds`

`makeDirectorKeyframes` preserves the caught application's exact `DomainError.code`. The set is open: it catches every per-scene `DomainError` except `TOOL_CALL_UNRESOLVED`, including errors propagated by composition, publication and injected application callbacks. This is an inventory of current scene, composition and publication guard codes; lower-level integrity checks and callbacks can propagate additional codes. It is not a new enum or restriction on future errors.

“Requested shots” below means the original call's explicit `shotIds` belonging to this scene, or all of the scene's shots when the call used `sceneIds`. A missing/empty scene therefore has `[]`.

| Exact code(s) | Filled `shotIds` |
| --- | --- |
| `ATTEMPT_EXISTS` | Distinct shots from the original `GenerationAttemptBlockedError.recovery.attempts`, before the tool receipt's cross-scene truncation. If this is the generic refusal without recovery, requested shots. `attempts` contains only `attemptId`, `shotId`, `kind`, `phase`, `action`; actions are `follow_existing_job` or `human_release`. |
| `DIRECTION_REQUIRED` | The known placeholder `details.shotIds`, intersected with requested shots; requested shots if no applicable detail exists. |
| `STALE_PROMPT_INTENT` | Known `details.shotIds` or `details.shotId`, intersected with requested shots; requested shots otherwise. Current compiler stale-prompt errors do not retain shot details, so they use that fallback. |
| `NOT_FOUND`, `SCENE_EMPTY`, `SCENE_REVIEW_STALE`, `SCENE_SELECTION_REQUIRED`, `SCENE_PLAN_INVALID` | Requested shots for each code. |
| `ALREADY_COMPLETE`, `CONFIRMATION_RUNNING`, `PROFILE_INCOMPATIBLE`, `NARRATION_SPEECH_UNAVAILABLE` | Requested shots for each code. |
| `SCOPE_DENIED`, `SCOPE_HELD`, `WAITING_USER`, `EXECUTION_PAUSED`, `TOOL_CALL_CANCELLED` | Requested shots for each code. |
| `ACTOR_DENIED`, `EPOCH_REVOKED`, `ORIGIN_NOT_AUTHORIZED`, `CAPABILITY_MISMATCH` | Requested shots for each code when encountered inside the scene loop. |
| `INSTALLATION_QUARANTINED`, `RESTORED_AUTHORITY_REQUIRES_NEW`, `RECOVERY_INVALID` | Requested shots for each propagated recovery refusal. |
| `REVISION_CONFLICT`, `PLAN_LIMIT`, `COMPILER_FAILED`, `PLAN_COMPOSITION_INVALID`, `SYNTAX_NOT_ALLOWED`, `DUPLICATE_NODE`, `UNKNOWN_REFERENCE`, `OUTPUT_TYPE_MISMATCH` | Requested shots for each propagated composition/compiler refusal. |
| `REVIEW_REQUIRED`, `REVIEW_SPEC_MISMATCH`, `CAPABILITY_UNSUPPORTED`, `DURATION_LIMIT`, `UNKNOWN_OPERATION`, `DEPENDENCY_CYCLE`, `INPUT_BINDING_MISMATCH` | Requested shots for each propagated composition/compiler refusal. |
| `TRANSCRIPTION_INPUT_INVALID`, `TRANSCRIPTION_INPUT_CONSUMER`, `PROFILE_CONFIGURATION_INVALID`, `LOCAL_EXECUTION_UNSUPPORTED`, `VALIDATION_ERROR` | Requested shots for each propagated validation refusal. |
| `WORKFLOW_REQUIREMENT`, `SHOT_SHORTER_THAN_NARRATION`, `STAGE_BINDING_CONFLICT`, `IDEMPOTENCY_CONFLICT` | Requested shots for each propagated publication refusal. |
| `APPLICATION_INPUT_UNAVAILABLE`, `OWNED_TRANSCRIPTION_AUTHORIZATION_INVALID`, `NARRATION_SPEECH_AUTHORIZATION_INVALID`, `DEFERRED_VIDEO_INVALID` | Requested shots for each propagated preserved-graph/installation integrity refusal; trusted valid construction normally prevents these. |
| `OWNED_TRANSCRIPTION_INVALID`, `NARRATION_SPEECH_INVALID` | Requested shots for each propagated retained-audio record validation refusal. |

Whole-call failures before the receipt/scene loop (initial authority, argument validation, an unknown explicitly requested shot, or re-entry of an existing receipt) create no scene block. Unexpected failures and `TOOL_CALL_UNRESOLVED` retain uncertain-outcome handling and also create no refusal block. Video-only guards such as `TIMING_REQUIRED`/`RECOMMENDATION_OPEN`, and the optional HTTP estimate guard `ESTIMATE_CHANGED`, are not Director keyframe refusal paths.

## Open issues

- No implementation blocker remains. UI rendering and browser replay belong to the lead and were not run under the card's server-only/no-browser rules.
- Decision: cap public blocks and attempt summaries at 20 across the turn while retaining every scene's immutable record; preserve known blocking shot identities even when the separate tool receipt has exhausted its attempt-detail allowance. Block order follows existing entity insertion order.
- Decision: use narrow known IDs for both stale and missing-direction prompt refusals; current compiler errors without details retain the requested-scene fallback. No compiler/tool contract was changed to manufacture additional detail.
- Decision: record historical refusal evidence under its already established original identity without requiring fresh spending authority. Reconciliation uses only that exact invocation's saved evidence and never resumes the remainder of an incomplete call.
- Refusal codes are an open set because existing application errors propagate; the UI should provide a generic fallback for an unfamiliar code.
- All checks use disposable state, fake transports and synthetic media. No browser, real provider/model call, external network request, credential read, production-state access/restart or port 3001 listener was used.
