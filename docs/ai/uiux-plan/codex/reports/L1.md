# L1 — Lost submission replies for all providers

## Done

- **L1.1 / Normalizer:** a taskless `failed` observation is accepted for every adapter only when `failureId` is exactly `SUBMISSION_RESPONSE_LOST` and `retryAllowed` is explicitly false. Ordinary taskless failures remain invalid except for the existing scoped native Codex image exception.
- **L1.2 / HTTP adapters:** MiniMax H3, OpenAI image, speech and transcription retain local receipt/output recovery, wait through the maximum permitted POST window, then return terminal technical `SUBMISSION_RESPONSE_LOST` with `taskId: null` and no automatic retry. A live reconciliation lease can transactionally seal a never-dispatched receipt; old first-dispatch workers are fenced, and the reservation is released. Unfenced reads cannot infer non-dispatch.
- **L1.2 / Narration and owned transcription:** the named `narration-speech-execution.ts` and `owned-transcription-execution.ts` files are authority resolvers, not separate providers. They already use the same OpenAI bridges. End-to-end admission/Engine tests verify both lost and never-dispatched outcomes through those paths; these helpers need no source changes.
- **L1.2 / Codex image:** preserved real `thread/read` recovery. A validated mapping saves a nonempty thread ID before dispatch; dispatch requires that same ID, and a run additionally requires a turn ID. Thus every valid dispatched record already has a real source identity. A dispatched state with neither ID is structurally impossible under the existing validators. Four preservation tests cover thread-only and thread-plus-turn recovery beyond the native timeout, fenced non-dispatch and completed receipt replay. The source change documents this invariant; it does not weaken receipt validation or invent corrupt fixtures.
- **L1.3 / Fake:** removed all attempt-ID job discovery from `lookup`. The fake POST has finished when lookup runs, so its lost response is immediately terminal. Known task IDs still poll normally, and submit still deliberately permits duplicates so tests can detect blind resubmission.
- **L1.3 / Consumers:** replaced impossible late lookup expectations with charged loss or genuine known-task/local-acceptance recovery. The offline 60-shot probe charges the lost clip, proves repeated reconciliation does not buy again, and requires a fresh simulated human press for its replacement (123 total fake accepts, 122 current output slots, zero duplicate attempt submissions).
- **L1.4 / Engine:** no source change. Accepted evidence recovery, Give up for unresolved known jobs, unknown backoff and event deduplication remain intact. Local execution is unchanged.
