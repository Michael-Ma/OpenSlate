### Reply-style before / after

Before, the host summary said:

> Organize summaries by scene and name one useful next decision. A valid draft is not accepted audio, reviewed image/video generation or finished footage.

Its alternate audio branch said:

> Organize summaries by scene and name one useful next decision. A valid draft is not accepted narration, approved frames, paid permission or finished footage.

Proposal instructions repeated “report a refusal and its current state without claiming success.” The v7 production entry ended with “Report actual saved progress and remaining choices. Tool receipts establish saved work, not artistic quality; describe known fixture media as placeholders.”

After, the host `replyStyle` and the first v7 Reply style paragraph say:

> Lead with concrete work saved, changed or started, using app-reported results and the price when returned. Then give one plain next step or the one action the person needs to take. Mention an unmet request only when the person asked for it, once, with a brief reason and a way forward. Keep replies concise in English and Chinese; omit unrelated disclaimers and unsolicited app rules or limits. In Chinese, omit 不代表/不能视为/不能评价/我不会/我没有 boilerplate.

The v7 evidence/reconciliation paragraph says:

> Only application evidence establishes that work started, was accepted or was saved. Keep an unknown outcome's original operation and call identities, inspect receipts and stop dependent work until reconciled; never resubmit blindly. Describe that requested work as "waiting for the service's answer", with the next step.

The host keeps its matching successful-receipt and unknown-outcome rules separately in `filmPlanning.truth`; native `instructions` refer to actual outcome evidence and requested-scope next actions without duplicating the reply-style section.
