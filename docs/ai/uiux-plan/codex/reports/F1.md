# F1: uploaded pictures and videos keep their file names

## Done

- **F1.1:** Image and video upload routes accept an optional `name` of 1–120 Unicode characters, excluding U+0000–U+001F, U+007F, `/` and `\`. A shared schema and service validator enforce the same bounds. The exact optional name participates in application-request and import-command identities, including explicit `requestId` imports; changing or removing it refuses replay. Unnamed imports omit the field and retain their previous digests.
- **F1.2:** Store names in immutable image/video import records and artifact metadata. Assets returns the name in `AssetItem.label`; existing Director attachment projection reads the same metadata for `MessageAttachmentView.name`. JPEG normalization retains the supplied `.jpg` name. Imports without a name retain their old labels. No migration or DDL is needed.
- **F1.3:** `uploadPath` sends the existing cleaned, URL-encoded optional filename for images and videos as well as audio/documents. The sample film uses the image/video query name for its asset/message labels and refuses changed-name replays.
- **F1.4:** Added backend/service and simulated-route coverage for named PNG/JPEG/video, unnamed fallback, invalid names, exact replay, changed/removed names, immutable metadata and caller mutation across asynchronous validation. Existing money/integrity tests remain enabled and unchanged.

## Open issues

Valid names without such an extension, or containing ` · `, are correctly stored and returned in `AssetItem.label`/`MessageAttachmentView.name`, but the existing tile formatter can still show a generic imported label. This card authorizes only the upload-path and simulated-route source files, so that formatter is left for the lead. Standard PNG/JPEG/video filenames are covered by F1's tests.
- **Validation decision:** Keep optional names exactly as supplied to the API, including whitespace, rather than silently trimming request identity. Browser uploads continue using the pre-existing `cleanName` sanitation. Existing audio/document validation and behavior are unchanged.
- **Acceptance boundary:** Browser launch/checks are reserved for the lead by `RULES.md`. Validation uses disposable local state, synthetic media, fake providers and scripted Director runs; no live model/provider call, external network request, personal credential read, production restart or port 3001 listener is used. No new live-provider or rendered-browser acceptance is claimed.
