# U1 — Director attachments

## Done

U1 is implemented except for installing the approved PDF dependency and validating real PDF extraction. The offline dependency blocker below prevents marking the whole card complete.

- **U1.1 — images:** uploads accept PNG, JPEG, WebP and HEIC. Published references are PNG; existing PNG bytes remain exact. Other inputs pass local, file-only FFmpeg normalization, the existing size/dimension/frame checks, and a decoder-level 8,294,400-pixel limit. A header-only probe rejects excessive dimensions before counted decoding. Undecodable HEIC returns `IMAGE_FORMAT_UNSUPPORTED`. A valid, generated 366-byte HEIC fixture decoded successfully with the pinned FFmpeg 8.1.1 and published a 16×16 PNG.
- **U1.2 — documents:** added authenticated `POST /documents/uploads?expectedHeadVersion=N&name=` for nonempty PDF/TXT/MD files up to 32 MiB. Upload intent, exact bytes, extracted text, artifact and receipt are owned and persisted. UTF-8 Chinese, filename handling, replay, concurrency, stale authority/head and failed publication are covered. Assets accepts the document kind/role and displays its name and PDF page count in the existing label field. The artifact content route downloads owned documents with an encoded filename. PDF parsing is implemented in a bounded worker but cannot currently execute because the approved package is absent.
- **U1.3 — messages:** `attachments` accepts one to eight different owned artifacts, alongside legacy `images`; their combined count is eight. Empty-text attachment messages work with omitted text or `text: ""`. Selection and projection receipts bind exact identities, order, message context, source bytes, recipe and toolchain. Images become small JPEGs; videos receive up to three start/middle/end stills with duration, dimensions and explicit picture-index/sample-time mapping. Owned audio-library recordings work without requiring a second artifact record and expose measured duration, WAV format and separate paid transcription availability. Documents enter `attachedMaterial` as bounded untrusted reference text, with explicit instructions never to follow embedded instructions. No attachment grants generation or acceptance authority.
- **U1.4 — thread:** user conversation entries expose `MessageAttachmentView[]` for generic attachments and legacy images. Names freeze with completed projection receipts. Unextracted or omitted content has `readable: false`; audio metadata is distinguished from hearing/transcribing speech. The scripted Director acknowledges the attached filenames without claiming to interpret them.
- **U1.5 — integrity and recovery:** changed/missing bytes stop preparation before model dispatch. Exact replay retains one request/turn/projection, and subsequent messages do not inherit attachments. Immutable entity validation covers new selections, projections and document imports/receipts. Installation backups retain document bytes and all eight legacy/generic picture slots, exclude staging, and reject a missing frozen projection.

No browser, real provider/model, external network request, personal credential or production-state access occurred. No listener was started on port 3001. Tests used disposable state, synthetic media and injected runtimes/extractors. No UI, frozen skill/tool catalog, DDL or implementation-status document changed. Independent source reviews found and resolved the compressed-image pixel-allocation issue and the missing actual audio/video metadata paths; no outstanding source finding remains beyond the PDF dependency blocker.
