# Card P1: the Director accepts a proposal when the person says so in the chat

Read `_review-common.md` in this folder first, with one exception: like N1, this card may amend tool contract 6.0.0 and skills v7 in place (never released; keep the current 6.0.0 catalog and v7 package identities in the shipped-identity list so projects saved on this branch still upgrade, and extend the pin test).

The owner tried N1 in a real conversation. They typed "接受提案 c，你开始生成所有的新的关键帧" and "你直接按照新的方向改就好，提案批准了". The Director answered "需要你点击该提案的 Now/After 预览接受按钮，我不能代点" and "文字回复不能替代该操作". The owner decided that is wrong: **when the person clearly tells the Director in their own message to accept (or decline) a named proposal, the Director does it.** The card in the chat and the banner stay; this adds the typed path.

1. **Tools (6.0.0 only; 5.0.0 and older byte-identical):** `accept_proposal` and `reject_proposal`, input `{ proposalId }` (accept the app-assigned letter too if the proposal's note has one, or document why only the id). They call the same `proposalCommand` as the human routes, so the effects are identical: same patch, same touched fields, same note settlement, same Undo.
   - Allowed only in a turn answering a human message with `source: "user"` (typed by the person), in an editing turn. Refused in turns started by an app message (`source: "app"`, e.g. "Director proposal accept.", "Resolve this Director note."), keyframe-review turns, automatic turns and read-only turns. Pick a stable refusal code and document it.
   - The application, not the model, uses the current `previewDigest` at the moment of the call. If the proposal is no longer held (accepted, declined, undone, stale) the call gets the same refusal a late human press gets; the Director then reports what state it is in, never claims success.
   - Record that the Director acted on the person's word: the receipt/event carries the human message id (`requestId`) and an actor marking "director on the person's request". Expose it in the `DirectorProposal` view so the web can say "Accepted from your message · Undo". The lead adds the matching field to `packages/core/src/studio-api.ts` only if you need a new one; add it yourself and list it under Contract changes.
   - First wins stays: if the person pressed accept in the banner a moment earlier, the tool gets the settled refusal, and vice versa. Concurrent tool call + human press accept once.
   - Undo of a proposal the Director accepted works from the web exactly as for a human accept.
2. **Guidance (skills v7, 6.0.0 host guidance, `film-planning-guidance.ts`, `director-input.ts`):** replace the N1 sentence "a chat reply such as yes/ok is not a confirmation" for proposals with:
   - If the person's message clearly asks to accept or decline a specific proposal (by letter, by its subject, or the only held proposal when there is exactly one and the message clearly refers to it), call `accept_proposal` / `reject_proposal`, then say in one line what changed and that it can be undone.
   - If it is ambiguous which proposal, or the message is only "ok"/"好的" with several open, ask which one (or point to the open cards). Never guess between several.
   - After accepting, continue with what else the person asked in the same message (e.g. "then generate all the new keyframes"), using the accepted prompts.
   - Video confirmation stays a `confirm_video` card only (it needs the frames opened first); keep that sentence. Paid keyframe generation already starts from the person's request as today; do not change it.
   - Remove every sentence that says chat approval cannot replace the app action, or "I can't press it for you", for proposals. Keep the guidance short.
3. **Fake director** (`fake-director.ts`): a path that accepts a held proposal when the user message says "accept proposal <letter>", for tests.
4. **Tests:** schema pins (6.0.0 has the tools, 5.0.0 refuses them); accept from a user-typed turn applies the patch, settles the linked note with the same resolution a banner accept gives, records the request id; refused in an app-message turn, a review turn, a read-only turn; stale/already-accepted gets the refusal; banner accept then tool call → refusal, tool then banner → refusal, simultaneous → one accept; undo after a Director accept restores; guidance tests no longer contain the old stance for proposals.
