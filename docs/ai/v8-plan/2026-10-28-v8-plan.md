## 对口型：H3 能不能直接做

- 我们现在调用的 Viggle `/v1/videos` 底层就是 **MiniMax-H3**（`packages/providers/src/viggle-h3.ts:21`），只接首帧/尾帧和 prompt，**没有音频输入**。H3 会生成自带音轨，但那是模型自己生成的声音，不会对上你的歌；把歌词写进 prompt 也只会让它"唱"自己的版本。
- **MiniMax H3 Max 有专门的 lip-sync 模式**：关键帧 + 一段音频 → 对口型视频（fal 上的 `minimax/h3-max/lip-sync/image-to-video`，768p 约 $0.08/秒，一个 6 秒镜头约 $0.48；超过 15 秒 ×1.2）。这就是"给 H3 加 reference audio"的做法，而且是同一个模型家族，画面风格和其他镜头一致。Viggle 自己的 API 目前没有这个端点。
- Viggle App 里的 Mic/Rap 可以对口型，但只在 App 里，API 没有。Viggle-Animate（驱动视频换角色）官方博客说特写的口型跟得不好。
- **方案**：唱歌镜头 = 关键帧 + 本镜头歌曲片段的人声 stem → H3 Max lip-sync，一步出片（不用先出片再做第二遍）；不唱的镜头照旧走 Viggle H3。A/B：同 2–3 个镜头对比 H3 Max lip-sync 与 sync.so `lipsync-2-pro`（后者是"先出片再对口型"，约 $4–5/分钟）。需要你自己配置 fal（或 MiniMax）API key。
- 风险：audio 驱动的模式动作以口型和上半身为主，载歌载舞的大动作镜头不适合，这类镜头规划成"不对口型"（技能草稿已有这条规则）。

## 音乐分析工具（"Astra"）

- 没查到叫 Astra 的音乐分析服务。最接近的是开源的 **STRATA**（github.com/wexloops/strata）：sections、beats/downbeats、调性、和弦、hits/drops、歌词，输出一份 JSON，并且自带 MCP。另一个是 All-In-One Music Structure Analyzer（tempo、beats、downbeats、intro/verse/chorus 分段）。**需要你确认 Astra 指的是不是 STRATA。**
- mv-audio 已经做了本地分析（tempo、beats、sections，按录音缓存，`GET audio-library/:audioId/timing`）。
- 计划：Director 新工具 `analyze_music {audioId}`，免费只读，返回 tempo、拍点、段落（含 verse/chorus 标签）、歌词时间轴（如果有）和每段的建议镜头时长。后端用一个可替换的 analyzer 接口：默认用现有本地分析；STRATA（或 All-In-One）作为增强 analyzer 补段落标签和歌词，作为本地进程运行，不上传音频。用户上传歌曲或说要做 MV 时，Director 先调它，再按 music-video 技能规划。

1. **Contract 7.0.0 + 服务端工具**（一个 agent，非 UI）：`set_soundtrack`、`read_context.audio_library`、`analyze_music`、`move_shot`/`move_scene`/创建时 `beforeId`、`start_export`、`undo_edit`、`delete_shots`/`delete_scene`（确认卡片）、`use_take`（确认卡片）、`control_execution` 的 stop/resume、角色读写和 `make_character_sheets`、`filmKind`、`project.visualStyle`。复用人按钮背后的同一套命令，6.0.0 不动。同时改掉 `director-input.ts:50` 和 `film-planning-guidance.ts:38` 里"音乐是人的操作"的说法。
2. **技能 v8**（我来汇总，依赖 1 的工具名）：production 8.0.0 和 plan-authoring 8.0.0，把四组草稿整理成 lazy references（video-types、visual-styles、music-video、characters），v7 不动。
3. **角色设定图执行层 + 路由**（一个 agent，和 1 并行，只碰执行层和角色路由）：不挂在镜头上的 image 节点、sheet 的生成/上传/批准，批准时同一个 revision 里绑定并让旧关键帧过期。
4. **对口型**（一个 agent，在 1 之后）：`performance: "singing"`、人声分离、H3 Max lip-sync adapter 和 sync.so adapter、价格 profile；A/B 要你批准花钱（约 $2）。
5. **UI**（我来做，在 1、3 之后）：Plan › Cast、设定图审阅面板、风格选择卡片、Director 的确认卡片（删除、用旧 take）、Film 的音乐分析展示。
6. **其他**：8–11 的四项交给 Codex 做（非 UI），和以上并行，文件不重叠。

每一步完成后跑 build、typecheck、全量测试和浏览器场景，提交到 `feature/last-ferry-ui` 并推送到 PR#1。
