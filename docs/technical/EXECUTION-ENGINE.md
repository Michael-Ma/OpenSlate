# Durable execution

The execution engine advances the saved graph through trusted providers and local media handlers. It owns candidate/attempt state and admission. The director does not poll every job or control provider recovery.

## Records and authority

A **node** is a planned operation. A **candidate** is a human-origin creative result slot. An **attempt** is one submission/recovery/retry under that candidate. A **receipt** records observed provider/local effects. An **artifact** is owned verified output. A current **binding** selects which candidate/output can satisfy the graph.

Configured admission rechecks the exact active candidate/node, pinned profile definition/options, credential/native/media readiness, epoch/hold/pause controls, accepted audio and exact keyframe review before video dispatch. It creates no usage allowance or hidden consumption step. Attempt/submission identity is committed before external effects. Technical retry requires trusted eligible failure evidence and bounded policy; it does not become a new aesthetic alternative.

Every attempt request carries an explicit adapter/version identity. Demo requests use fake/v1 without a configured profile snapshot; missing identity never selects the demo adapter. Saved graph capability locks require the current recipe digest, and graph video dispatch requires an explicit silent-shot decision or accepted measured narration. Provider failure/rejection outcomes carry an explicit `retryAllowed` boolean; incomplete outcomes remain unknown and cannot authorize a retry.

## State and recovery

Attempt phases include `preparing`, `submitting`, `remote_pending`, `submission_unknown`, `ingesting`, `succeeded` and `failed`. Preparation can retain owned conversion work while media inputs are not ready; current selection is checked again before the first paid dispatch.

Leases use owner/epoch/expiry. A stale worker cannot mutate current state. An expired `submitting` lease becomes uncertain, because process failure does not prove that the vendor rejected the request. Recover the same task/receipt/output; never resubmit merely because observation timed out.

Provider results are retained even when a user edit supersedes their slot. Late completion can be historical evidence without replacing the new selected output. A positive no-dispatch proof may release known-unsent work; unknown effects retain liability. Unknown outcomes and lost synchronous image bytes can require human/account reconciliation.

## Publication

1. Retain immutable dispatch/observation receipt.
2. Save raw outputs through bounded durable spooling.
3. Decode/probe and normalize owned image/video/audio/transcript/timeline output.
4. Retain normalization/completion receipt before SQL selection publication.
5. Publish compatible bindings under the current lease/selection; recover missing SQL acknowledgement from the same immutable evidence.

Files are outside short database transactions. [Output storage](../implementation/OUTPUT-SPOOL.md) and [provider artifacts](PROVIDERS-ARTIFACTS.md) define their validation boundary. Restored installation quarantine blocks recovery until explicit release, and old unused imported authority cannot start new generation afterward.

## Code plans (experimental)

Contract 0.3.0 adds `ctx.review(id, {clips, note})` and the free `read_clip_frames` tool. A review stops the pass with run state `reviewing`, keyed by id and clip digest; the scheduler starts one application Director turn when no other turn, question, Stop or hold is active. Any terminal turn settles the review and replays the current plan, so a film never waits on one. A film gets four review turns (`CODE_PLAN_REVIEW_TURNS`); later reviews return at once with a log line. Contact sheets are rebuilt on replay: only their hash and size enter `tool_invocation`, never image bytes. 0.1.0 and 0.2.0 films keep their archived guidance and have neither capability.

`ctx.image` takes owned `references` and an `aspectRatio`, checked at dry run. `render` adds row `speed`, `holdFrames` and fixed `zoom`, finished-film `captions`, `fadeInSamples` and built-in sounds; absent fields stay out of normalized input, so saved plans keep their step keys. Captions are transparent PNGs drawn with the system's fonts, frozen in the manifest with the font's identity. 0.3.0 films master the mix with measured two-pass `loudnorm` (I=-14, TP=-1.5, LRA=11). Viggle crops first and last frames independently to the requested ratio; references stay uncropped.

N7 installs a built-in `viggle-h3` profile whenever the host enables the Viggle route; no provider configuration file is needed. It pins adapter `viggle-h3`/execution version `1`, `MiniMax-H3`, low quality, 768p and 150–450 frames (5–15 whole seconds), with one concurrent attempt and no automatic vendor retries. Its legacy per-call estimate is $0.75, covering the longest reference/first-and-last-frame clip; code-plan reservations still use the exact N6 input table. The default profile ratio is 16:9, while code input can explicitly select any supported ratio or infer one from owned images.

For new code films, `codeMediaProfiles()` includes the built-in instead of configured Viggle profiles, retaining every other ready video/music model. Trusted creation selections map a configured Viggle choice to the built-in and record the resulting profile id in provenance. The graph selection path keeps the original configured bytes. Configured profiles remain installed for graph and saved code films; no saved lock, input, step key, receipt or recorded price is upgraded. A conflicting custom definition using the reserved `viggle-h3` id is refused; custom historical profiles must use their own ids. No schema or browser contract changes are required.

Every human message's attachments now reach a code-film turn through the same projector as storyboard films. `read_film` and `context.film` also list `uploads`, the newest 24 distinct supplied pictures, because each turn starts a fresh thread. `read_clip_frames` shows an owned picture as one JPEG without persisting it. A failed copy never fails the turn: the listing shows the original with `imageReferences: false`.

`ctx.keyframe(shot, input)` composes an ordinary image step and an ordinary `<shot>-keyframe` choice inside one replayed host call. Its options keep the frame's artifact fields flat and add `keyframeInput`, `references`, `video` and `priceMicros`, so a changed picture, duration or model asks again. In a 0.3.0 pass that declares shots, a new video step needs a keyframe confirmed in that pass, and its images must honour the answer: `references_only` forbids the frame, the other two require it. Only previously dispatched or returned clips are exempt, so saved films and re-cuts replay unchanged; a never-dispatched cancelled row cannot bypass the gate. In Assets an image step linked to no shot has role `reference`.

A choice is current exactly when the latest finished pass of the current version reached it, through `ctx.choose` or `ctx.keyframe`. At the end of such a pass every unreached row is marked `stale`; an errored, stopped or superseded pass marks nothing, and `submitPlan` resets nothing, so a card that survives a new version does not flicker. A row records `askedAt` when it is created, and again when an unanswered stale row is reached once more; older rows are dated from their frame step. A stale row refuses a new answer with `CODE_PLAN_CHOICE_STALE`, while repeating the stored answer still succeeds. `read_film` omits stale rows; the browser view keeps them as history. A retired keyframe choice still links its frames and clips to their shot, but not a step the latest pass reaches without it. The keyframe gate exempts only journaled clips with an attempt or a result.

Every video row in `read_film.models` now reports `aspectRatios`, effective `durationSeconds: {min, max}` and N6's `videoModes`. The duration interval intersects vendor policy with the saved profile: `viggle-live-six-seconds` still reports 6–6 seconds and all six ratios. Seedance ratios and model limits and fal ratios/limits come from their existing provider definitions. Adaptive/auto entries describe image-driven ratios; MiniMax reports adaptive. Veo also exposes `durationValuesSeconds`, intersected with the profile, so its discrete 4/6/8-second choices are not misrepresented as a continuous interval. Invalid profile durations are refused in the dry run before intent admission, with the model's saved range in the message.

Current guidance treats these model facts as authoritative and never sends the person to a maintainer to confirm capabilities. After generation, actual dimensions and duration must come from measured `read_film.steps[].output` facts, shared with `GET /code-plan/steps/:stepKey`, rather than being inferred from requested settings. Only the current code-plan package and its digest pin change; `skills/code-plan-v1` remains untouched.

References are normalized ordered image content identities and must resolve to this film's owned artifacts. Viggle accepts 1–4 images up to 20 MiB each; Seedance accepts 1–9 and still refuses realistic human faces. Every new code-plan Viggle attempt explicitly sends `enhance=false`; Studio and profiles cannot enable prompt rewriting. A single provider-package price function serves previews, reservation and historical authority checks. Viggle uses `priceUnit: "input"`: `ceil(durationSeconds) × creditsPer5Seconds ÷ 5 × $0.01`, with mode, resolution and enhancement selecting the card's published table. Validated failed/cancelled Viggle tasks release their liability; lost submission replies retain it.

Receipts without `enhance`/`references` retain their original digests and saved flat price. Replaying a completed saved step buys nothing. A new attempt of that same step records `enhance=false` and today's table price without rewriting previous attempts or liabilities. Graph films retain their original admission, first-frame behavior and configured estimates.

The archived `code-plan-v1` package is unchanged.

`CodePlanRuntime` implements the lead-owned `CodePlanPort`. `view` projects the current run, reached/history steps, choices with original question time and stale history and the latest 50 versions with their saved dry-run diffs; an untouched project is `empty`. In-flight work, zero-price calls and local renders continue. Release wakes replay; multiple holds and their release states survive restart.

A restarted intent itself never resubmits. Completion is persisted before the shared ingestion router publishes owned, hash-verified artifacts. Real media uses the installed registry's Codex image, OpenAI Images, Viggle H3, MiniMax H3, Seedance, fal video, Lyria music and OpenAI speech adapters, with their existing credential resolution, egress policy, exact receipts, raw output spools and image/video/audio ingesters. The first irreversible marker rechecks the original plan version, profile lock, lease, Stop, priced holds and reserved ceiling. In-flight recovery uses historical pins independently of later edits. A definitive rejection or validated free terminal task failure releases liability. The view splits charged/possibly-charged (`spentMicros`, including unknown submissions) from pending reservations (`reservedMicros`). A ceiling change persists and wakes replay. Zero estimates for other real profiles remain explicitly unpriced, contributing zero known dollars. These are configured estimates, not validated bills. Graph quotes retain their configured per-call basis. Unpriced calls contribute zero known cost; they may still incur real vendor charges. The default 200-step project limit counts every admitted attempt across all versions, including retries: absent, held, budget-blocked and cancelled work consume no slot. Provider timeouts stay uncertain; shutdown drains owned work before closing the store.

## Code-plan film-quality execution (0.3.0)

`ctx.image` makes shared reference pictures with validated ordered owned references and supported aspect ratios. `ctx.keyframe(shot, input)` makes one shot picture, then waits for a priced human video-input choice. New video for a declared shot must match that confirmation; only already-dispatched clips are exempt on replay. A plan without shot declarations is not gated. Shared references and in-progress keyframe/clip slots project into Plan without creating extra execution authority.

`ctx.review` records a latest-pass review and pauses for a Director turn, with a per-film four-review bound. Free `read_clip_frames` returns a labelled 30 fps contact sheet (up to 36 cells) and motion measures; owned images return one bounded JPEG decoded through FFmpeg, including Codex PNGs with C2PA metadata. Uploads supply owned bounded reference copies and remain available through `read_film.uploads`. No soundtrack is played to the Director.

Code-film `render` also supports source trims, speed, holds, fixed zoom, captions, local sound placements and fade-in/out. Its frozen manifest retains exact inputs and mastering identity; legacy absent fields preserve historical keys. See [timeline/rendering](TIMELINE-RENDERING.md#code-plan-editing-and-mastering-030).
